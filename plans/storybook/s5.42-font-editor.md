# S5.42 — Per-Block Font Selection in Layout Editor

**Status: Needs Verification**
**Branch:** journal-updates
**Depends on:** S5.41 (extended theming — book theme fontClass must be working)

---

## Overview

S5.41 makes each book theme carry a `fontClass` that applies globally to all text blocks. This session adds per-block font overrides: users can select a font for individual text blocks in the layout editor. The theme still sets the default; any block can override it independently.

No database migration needed — `fontFamily` is stored inside the existing `layout_data` JSON column.

---

## Data Model

Add optional `fontFamily` field to text block objects:

```json
{
  "type": "text",
  "x": 0.04, "y": 0.04,
  "width": 0.92, "height": 0.38,
  "content": "Hello world",
  "fontFamily": "serif",
  "id": "b-abc123"
}
```

Existing blocks without `fontFamily` fall back to `theme.fontClass` — no migration needed.

Font options (all currently loaded in the project):

| `fontFamily` value | Tailwind class | Typeface |
|---|---|---|
| `'serif'` | `font-serif` | Georgia / system serif |
| `'sans'` | `font-sans` | Inter |
| `'display'` | `font-display` | Poppins |

## Changes Per File

### `Frontend/src/components/storybook/LayoutEditor.jsx`

#### 1. `TextBlock` — font resolution

```js
const FONT_MAP = { serif: 'font-serif', sans: 'font-sans', display: 'font-display' };

function TextBlock({ block, cs, theme, isEditing, onStartEdit, onStopEdit, onFontChange }) {
  const fontClass = FONT_MAP[block.fontFamily] ?? theme?.fontClass ?? 'font-serif';
  // use fontClass everywhere font-serif was hardcoded
}
```

#### 2. Font picker UI

Show a small 3-button picker when a text block is active (selected or in edit mode). Place it in the block's bottom toolbar or as a floating strip beneath the selected block.

```
[ Aa serif ] [ Aa sans ] [ Aa display ]
```

- Each button label rendered in its own font so users can see the difference
- Active font gets a highlighted border
- On click: calls `onFontChange(block.id, fontFamily)` — or `null` to clear override and revert to theme default

#### 3. `handleFontChange` in `LayoutEditor`

Add alongside existing block update handlers:

```js
function handleFontChange(blockId, fontFamily) {
  setBlocks(prev =>
    prev.map(b => b.id === blockId ? { ...b, fontFamily: fontFamily ?? undefined } : b)
  );
  // trigger auto-save (same pattern as other block mutations)
}
```

Pass `onFontChange={handleFontChange}` and `theme={theme}` down to `TextBlock`.

### `Frontend/src/components/storybook/LayoutRenderer.jsx`

In `renderBlocks(blocks, cs, theme)`, resolve font per-block instead of once for all blocks:

```js
const FONT_MAP = { serif: 'font-serif', sans: 'font-sans', display: 'font-display' };

// inside the block.type === 'text' branch:
const fontClass = FONT_MAP[block.fontFamily] ?? theme?.fontClass ?? 'font-serif';
```

## Verification

- Open layout editor on a published chapter with text blocks
- Tap/click a text block → font picker appears
- Select "Display" → block renders in Poppins in both editor and published view
- Select a different block → picker shows that block's current font (or theme default if unset)
- Save and close → font persists on reload
- Existing chapters with no `fontFamily` on blocks still render using the active theme font
- Switching book theme changes font of unoverridden blocks but not overridden ones
