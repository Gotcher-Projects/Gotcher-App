# S12.3 — Crop to Slot (Phase 2)

**Status: Not started**
**Branch:** same as S7
**Depends on:** S12.2 verified (Phase 1 must be live first)
**Roadmap:** builder-rewrite roadmap; decisions in `s12-templates-photos-polish.md`

---

## Goal

When a photo is placed into a template slot, open a crop modal sized to that slot's actual aspect
ratio so the user frames the shot intentionally. Persist the crop on the block so the framing is
stable across template changes and re-renders.

---

## Background

After S12.2, every photo entering the builder is cropped to `4/3` or `3/4`. But template slots have
their own aspect ratios — a tall narrow Side-by-Side photo slot is very different from the wide
Classic photo block. Today all slots use `object-cover` with a center crop, and the user cannot
adjust framing once a photo is placed.

**S12.2 confirmed this is needed.** After shipping S12.2, photos placed into slots with a different
aspect ratio than the crop were visibly cut off on the sides (landscape photo in a portrait slot)
or top/bottom. A blurred background fill + `object-contain` was tried as a band-aid but was reverted
— it made the mismatch more obvious rather than less. The correct fix is this plan: crop to the
slot's actual AR at placement time so no letterboxing or clipping occurs at all.

---

## Scope

### 1. Extend the block data shape

Photo blocks currently store `{ type, x, y, width, height, url, sourceKey, label, contentSource }`.
Add an optional `crop` field:
```js
crop: {
  x: 0,      // left offset as fraction of original image width (0–1)
  y: 0,      // top offset as fraction of original image height (0–1)
  width: 1,  // crop width as fraction of original (0–1)
  height: 1, // crop height as fraction of original (0–1)
}
```
Absence of `crop` means "use object-cover center" — fully backwards-compatible.

### 2. Open crop modal on photo placement

In `ScrapbookBuilder.jsx`, when a photo piece is dropped/placed into a slot (`placeIntoSlot` or
equivalent), intercept to:
1. Compute the slot's aspect ratio from its normalized `width` / `height` in the template block
2. Open `openCropModal` with the photo's URL and the slot's aspect ratio
3. On confirm, persist the returned `cropRect` as `block.crop`
4. On cancel, leave the slot empty (or revert to the previous photo if replacing)

The crop modal in `lib/imageUtils.jsx` currently accepts a fixed ratio. Confirm whether it accepts
a custom ratio or needs to be extended to support arbitrary slot aspect ratios. If not, extend it.

### 3. Re-croppable from the slot

Add a small "re-crop" affordance (e.g. a scissors or crop icon) when a placed photo slot is
selected. Tapping it re-opens the crop modal for that slot with the same aspect ratio. On confirm,
update `block.crop`.

### 4. Render using stored crop

In the canvas renderer (`LayoutRenderer.jsx` / `bookCanvas.jsx`), when a photo block has a `crop`
field, apply it instead of plain `object-cover`:
- Use `object-fit: none` + computed `object-position` and `width`/`height` override, or
- Render the image inside a clipping container with explicit offset math

Exact rendering approach to be decided at implementation time based on whether the renderer uses
DOM or canvas.

---

## Reuse / touch points

- `Frontend/src/lib/imageUtils.jsx` — may need to accept a custom aspect ratio param
- `Frontend/src/components/storybook/ScrapbookBuilder.jsx` — intercept placement, add re-crop affordance
- `Frontend/src/components/storybook/LayoutRenderer.jsx` — use `block.crop` when present
- No backend or API changes — `crop` is stored client-side in `layout_data`

---

## Out of scope

- Cropping photos that are already placed before this plan ships (no migration)
- First Times photo cropping — separate concern
- Zoom/pan UI (drag-to-reframe) — this plan uses a modal; focal-point drag is a future option

---

## Open questions (resolve at session start)

1. Does `openCropModal` accept an arbitrary aspect ratio, or only landscape/portrait toggle?
2. Should placing a photo always trigger the crop modal, or only when the slot ratio differs
   significantly from `4/3`/`3/4`? (Always is simpler; conditional is less friction.)
3. What should happen when a template is changed and an existing photo's crop no longer matches
   the new slot's aspect ratio — clear the crop, or keep it?

---

## Verification

1. Drop a photo into a tall slot — crop modal opens pre-sized to that slot's aspect ratio.
2. Drop a photo into a wide slot — crop modal opens at the wide ratio.
3. Confirm crop — photo renders with the chosen framing, not object-cover center.
4. Re-crop affordance appears on a placed photo slot; clicking it re-opens the modal.
5. Updating the crop and confirming updates the framing immediately.
6. Blocks without a `crop` field still render correctly via object-cover (no regression).
7. Layout data saved to the backend includes the `crop` field and round-trips correctly.
