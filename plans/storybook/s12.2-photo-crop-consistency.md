# S12.2 — Photo Crop Consistency (Phase 1)

**Status: Not started**
**Branch:** same as S7
**Depends on:** S12.1 complete (or can run in parallel — no shared files)
**Roadmap:** builder-rewrite roadmap; decisions in `s12-templates-photos-polish.md`

---

## Goal

Make every photo that enters the builder go through the same crop step, regardless of where it came
from. Today the wizard crops on upload; the builder's `PhotoTray` uploads raw with no crop at all.

---

## Background

Two upload paths exist today:

**Wizard (`StorybookWizard.jsx`)** — step 2 "Add/Replace photo" calls
`openCropModal(file, onComplete, onCancel)` from `lib/imageUtils.jsx`. Crops to `4/3` landscape
or `3/4` portrait based on image orientation, then uploads the cropped blob.

**Builder (`PhotoTray.jsx`)** — `handleFile` function calls `apiUpload` directly with the raw file
(line ~17–19). No crop step. Photos land in the builder uncropped and are silently center-cut by
`object-cover` at whatever the slot aspect ratio happens to be.

This inconsistency means photos uploaded via the builder often look worse than those added through
the wizard, and users have no chance to fix the framing at upload time.

---

## Scope

### 1. Wire `PhotoTray` through `openCropModal` before upload

In `PhotoTray.jsx`, the `handleFile(file)` function currently does:
```js
const form = new FormData();
form.append('file', file);
const data = await apiUpload(`/storybook/${chapterId}/chapter-photos`, form);
onUploadDone({ sourceKey: data.key, url: data.url, label: data.label || '' });
```

Change to:
1. Import `openCropModal` from `@/lib/imageUtils`
2. When a file is selected, call `openCropModal(file, onComplete, onCancel)` first
3. In `onComplete(croppedBlob)` — proceed with the existing `apiUpload` call using the cropped blob
4. In `onCancel` — do nothing (treat as if the user didn't pick a file)

The crop modal already handles orientation detection and aspect ratio selection — no changes needed
to `imageUtils.jsx`.

### 2. Verify the crop modal renders correctly inside the builder

The builder is a full-screen panel. Confirm the crop modal (which is likely a fixed/portal overlay)
renders above the builder's z-index stack without clipping or z-index conflicts. Fix stacking if
needed.

## Reuse / touch points

  `openCropModal(file, onComplete, onCancel)`
- No backend changes — the upload endpoint receives a blob either way
