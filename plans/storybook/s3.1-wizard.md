# Session 3.1 — Chapter Creation Wizard
**Status:** Not started
**Branch:** `feature/storybook`
**Depends on:** S2 complete (generation pipeline), S3 (in-app storybook view)

## Goal

A guided wizard that lets users create a period chapter in one flow: choose a time window, curate which journal entries and first times to include, add supplementary memories, manage photos, and generate — ending on a book-like review UI. Lives alongside the existing event-chapter unlock flow; does not replace it yet.

---

## What this is NOT

- Not a replacement for the existing milestone/first_time event chapter flow (yet — likely replaces it eventually)
- Not generating multiple periods in one session — one period per wizard run
- Not passing photos to Claude — photos are for the book layout only, not the text prompt

---

## Predefined Period Buckets

The period selector is driven by a single constant (not hardcoded in multiple places) so it's easy to update or extend to custom ranges in a future session.

| Label | Week Range |
|-------|------------|
| Weeks 1–4 | 0–4 |
| Months 1–3 | 4–13 |
| Months 3–6 | 13–26 |
| Months 6–9 | 26–39 |
| Months 9–12 | 39–52 |

Periods that already have a published chapter for this baby are shown as disabled (greyed out with a "chapter already created" note).

---

## Wizard Steps

### Step 1 — Pick a Period
Selectable cards for each predefined period. Disabled if a published chapter already exists for that period.

### Step 2 — Curate Source Material
Show all journal entries AND first times within the selected week range. Each item displays:
- Title / label
- Date
- Story / notes snippet (truncated to ~2 lines)
- Photo thumbnail if one exists
- Checkbox to include

User selects which items to include. At least one item must be selected to proceed.

**Photo management per item:**
- Has a photo → show thumbnail, "Replace photo" button → opens Cloudinary upload
- No photo → "Add a photo" button → opens Cloudinary upload
- Uploaded / replaced photos are stored only on the chapter (`photo_overrides`) — the original journal entry or first time record is never modified
- After any upload/replace, show the note: *"This photo will only appear in your storybook chapter. Your original entry hasn't been changed."*

### Step 3 — Add Your Memories
Free-text area with prompt: *"Is there anything else you'd like to include in your baby's memory book for this time?"*

Optional — user can skip. Gets saved as `supplementary_notes` on the chapter.

### Step 4 — Generate
Progress indicator while Claude generates. Include a note: *"This usually takes 10–20 seconds."*

### Step 5 — Review (Book-Like UI)
Display the generated chapter in a layout that approximates the physical book:
- Chapter heading: period label (e.g. "Months 1–3")
- Generated body text
- Photos from selected entries interleaved with brief entry labels, using `photo_overrides` where set
- Action bar: **Edit** (body text) / **Regenerate** / **Publish**

Publish → sets status to `published`. Regenerate → calls generate again with the same selected IDs and notes.

## Schema Changes

### New migration — V28

```sql
ALTER TABLE storybook_chapters
  ADD COLUMN selected_journal_ids  BIGINT[]  DEFAULT NULL,
  ADD COLUMN selected_first_time_ids BIGINT[] DEFAULT NULL,
  ADD COLUMN supplementary_notes   TEXT      DEFAULT NULL,
  ADD COLUMN photo_overrides       JSONB     DEFAULT NULL;
```

`photo_overrides` key format: `"{source_type}:{source_id}"` → image URL  
Example: `{"journal:5": "https://res.cloudinary.com/...", "first_time:2": "https://..."}`

### WizardRequest DTO

```java
record WizardRequest(
    String anchorLabel,            // e.g. "Months 1–3"
    Integer periodStartWeeks,
    Integer periodEndWeeks,
    List<Long> selectedJournalIds,
    List<Long> selectedFirstTimeIds,
    String supplementaryNotes,     // nullable
    Map<String, String> photoOverrides  // nullable — key: "journal:5", value: image URL
)
```

### New endpoint: POST /storybook/wizard

Combines unlock + persist wizard fields + generate in one request. Returns the generated `ChapterResponse`.

1. Unlock (or re-use existing unlocked chapter) for `anchor_type = 'period'`
2. Persist `selected_journal_ids`, `selected_first_time_ids`, `supplementary_notes`, `photo_overrides` onto the chapter row
3. Check tier + credits, decrement, call Claude, update status to `draft`
4. Return full `ChapterResponse`

If a chapter already exists for that period (idempotent), update the wizard fields and regenerate.

### buildPrompt() — use curated source when available

When `selected_journal_ids` is non-null on the chapter:
- Query journal entries by those exact IDs (not the full week range sweep)
- Same for `selected_first_time_ids`
- Append `supplementary_notes` as a final section if present:
  ```
  Additional memories from the parent:
  {supplementaryNotes}
  ```
- Milestones: still auto-swept from the week range as background context (not user-selectable — see S3.5 notes)

When `selected_journal_ids` is null (existing event chapter flow), fall back to the existing range query unchanged.

### Dynamic max_tokens

```java
private int computeMaxTokens(int journalCount, int firstTimeCount, boolean hasNotes) {
    int tokens = 400
        + (journalCount * 150)
        + (firstTimeCount * 100)
        + (hasNotes ? 200 : 0);
    return Math.min(tokens, 2000);
}
```

Change `ClaudeClient.generateChapter(String prompt)` to `generateChapter(String prompt, int maxTokens)`. Remove the `MAX_TOKENS` constant. The existing event-chapter flow should pass a default of 600 to preserve current behavior.

### ChapterResponse — add wizard fields

Add to `ChapterResponse`:
- `List<Long> selectedJournalIds`
- `List<Long> selectedFirstTimeIds`
- `String supplementaryNotes`
- `Map<String, String> photoOverrides`

The frontend uses these to reconstruct the book-like review UI (which entries to show, which photos to use).

## Frontend Changes

### New files

| File | Purpose |
|------|---------|
| `Frontend/src/components/storybook/StorybookWizard.jsx` | Full wizard (steps 1–5) |
| `Frontend/src/components/storybook/BookChapterReview.jsx` | Book-like review UI (step 5, also reusable in storybook view) |
| `Frontend/src/lib/storybook.js` | API helpers: `startWizard()`, `regenerateChapter()`, `publishChapter()` |

### StorybookWizard.jsx

Multi-step form with internal `step` state (1–5). Fetches journal entries and first times for the selected period from existing endpoints when entering step 2. Calls `POST /storybook/wizard` on step 4.

Period options should be driven by a constant (same constant the backend conceptually mirrors):

```js
export const STORYBOOK_PERIODS = [
  { label: 'Weeks 1–4',   startWeeks: 0,  endWeeks: 4  },
  { label: 'Months 1–3',  startWeeks: 4,  endWeeks: 13 },
  { label: 'Months 3–6',  startWeeks: 13, endWeeks: 26 },
  { label: 'Months 6–9',  startWeeks: 26, endWeeks: 39 },
  { label: 'Months 9–12', startWeeks: 39, endWeeks: 52 },
];
```

Export this from a shared location (e.g. `Frontend/src/lib/storybookPeriods.js`) so it can be reused wherever periods are displayed.

### BookChapterReview.jsx

Renders step 5. Layout:
- Chapter title (period label) in a display font
- Generated body text in readable prose styling
- Below the text: interleaved entry labels + photos (from selected entries, using `photoOverrides` where present)
- Action bar at bottom: Edit / Regenerate / Publish

This component should be designed for reuse in the main storybook tab view for published chapters.
