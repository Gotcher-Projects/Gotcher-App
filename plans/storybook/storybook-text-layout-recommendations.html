Storybook — Text Fit & Repetitive Openings

Recommendations to feed a future implementation plan · CradleHQ · mapped 2026-05-30 · companion to plans/storybook/storybook-context.md. Earlier diagnosis of the same surface lives in storybook-layout-findings.html (repo root, S5.45).

The single most important framing: both problems you described come from one generation path — “One Page Per Memory” mode (generate-pages → SINGLE_ENTRY_SYSTEM_PROMPT). In that mode each page is a separate, independent Claude call using an identical prompt, so (a) every page is told to write in "You did… / You were…" → they all open with “You”, and (b) every page targets ~60–100 words regardless of how much room the page has → short, photo-less pages leave the lower two-thirds empty. The “One Story” woven path has the same opener tendency but, being a single call, is much easier to vary.

1 · What the system does today (the relevant slice)

  • Page-per-memory layout it builds (StorybookWizard.handleGeneratePages): a text block at y 0.04, height 0.92 when there’s no photo (or 0.34 with a photo above a 0.56 photo). On a 600×800 page that text box is the whole page.
  • fitText (useFittedFontSize) only shrinks. It binary-searches the largest font that fits the box, capped at the 15px base. It will never enlarge short text to fill, so a 40-word memory renders at 15px in a 730px-tall box → mostly whitespace.
  • No per-page title, date, or age is rendered on generated pages, so consecutive pages are structurally identical (text block, optional photo) — which compounds the “they blend together” feeling.
  • The woven SYSTEM_PROMPT also mandates the same closing move on every chapter (“close with a brief forward-looking line…”) — repetitive across chapters, not just openings.

Current prompts (verbatim, from ClaudeClient.java)

SINGLE_ENTRY_SYSTEM_PROMPT — used by “One Page Per Memory”

You are writing a single page in a baby's memory book, capturing one specific moment or
milestone. Write in second person, addressed to the baby ('You did…' / 'You were…').
LENGTH: Write 1–2 short paragraphs, about 60–100 words total, that capture this single
memory warmly and specifically. This is one page in a printed book, so brevity matters —
never exceed two short paragraphs. Do not pad or add content not in the source.
STRICT RULES:
(1) Only reference people and relationships explicitly named in the entry.
(2) Do not infer parent genders or count. Use 'the people who love you' if unclear.
(3) Tone: heartfelt and warm, never saccharine.
(4) No title, no photo markers, no forward-looking closing line — just the paragraphs.

SYSTEM_PROMPT — used by “One Story” + single-chapter generate

You are writing a chapter in a baby's memory book. Write in second person, addressed to the
baby ('You did…' / 'You were…').
LENGTH: For each memory or event provided, assess its richness — a brief note may earn 1
paragraph, a detailed entry with personal context may deserve 3–4. Write exactly as many
paragraphs as the content genuinely earns. Do not pad with generic filler, repetition, or
sentiment not in the source. Maximum: 25 paragraphs.
STRICT RULES:
(1) Only reference people, relationships, and events explicitly named in the journal entries.
(2) Do not infer how many parents are present, their genders, or anyone's relationship…
(3) Never write 'your dad', 'your mom', or 'the two of us' unless those exact relationships
    appear in the source text. If silent, describe the baby's actions or use 'the people who love you'.
(4) Do not add emotional reactions, physical details, or sensory color not in the source.
(5) Use 'we' only if the journal entries themselves use 'we'.
(6) Tone: heartfelt and warm, never saccharine.
(7) Photo markers: when a 'Photos available:' line is present, place [PHOTO:journal:42] /
    [PHOTO:first_time:42] on its own line after the most relevant paragraph.
STRUCTURE: Open by grounding the reader in a specific moment or sensory detail from the
earliest entry — not a general scene-setting sentence. Close with a brief forward-looking
line that points toward what is still to come.

2 · Problem A — short / photo-less pages waste space

Two complementary levers: change what the AI writes (more, better-shaped text) and change how the page renders it (let it breathe by design, not by accident).

Generation-side prompt / backend

#RecommendationWhy it helps
A1★ Raise the length floor and allow gentle reflective framing. Bump the target from “60–100 words” to roughly 90–160 words, and relax rule (4)’s “do not pad” into a precise allowance: you may add a reflective closing beat and lightly evoke the season / the baby’s age, but never invent specific events, people, places, or quotes. Highest-leverage fix. The current prompt actively forbids the very thing that would fill the page. A slightly longer, grounded reflection fills the box with real content rather than air.
A2 Return decorative fields the layout can place: a short pullQuote (one lyrical line distilled from the body) and a code-computed dateLabel (e.g. “Spring · 4 months old”, derived from week + birthdate, not from the AI). Turns empty space into designed space: a large pull-quote and a date/age header read as intentional layout, not a half-finished page.
A3 Merge thin, adjacent memories. When several selected memories are short and close in time/theme, combine them onto one richer page (or steer the user toward “One Story” for sparse periods). Could be a grouping pre-pass or a “suggested page count”. Stops the system from spending a whole page on a one-line memory.

Layout / render-side frontend

#RecommendationWhy it helps
A4★ Let fitText grow, not just shrink. Allow the fitted size to exceed the 15px base up to a sane ceiling (≈1.6–1.8×), and vertically center short text blocks. Directly fixes “small text in a big box.” A short memory scales up to a comfortable size and sits centered instead of clinging to the top-left. The ceiling stops a 5-word memory becoming a billboard.
A5 Content-aware default template when building generated pages — pick by (text length × has-photo):
  • short + photo → hero photo with a caption band
  • short + no photo → centered “quote card”: large display text, generous margins, a divider/sticker accent, date label
  • long + photo → photo as accent, text dominant (drop cap)
  • long + no photo → full-bleed text with drop cap
 Replaces today’s single fixed split. A sparse page gets a layout that’s meant to be sparse.
A6 Decorative fill primitives: date/age header, theme divider (theme.dividerChar), drop cap (the .book-rich first-letter cap already exists), an auto-placed sticker, framed photo + caption. Cheap, on-brand ways to occupy space meaningfully.
A7 (Optional, print economy) two short memories per spread — pack very short ones together instead of one-per-page. Fewer near-empty pages overall; better for the eventual PDF/print product.

3 · Problem B — every page opens with “You” / pages blend together

Generation-side prompt / backend

#RecommendationWhy it helps
B1★ Stop instructing “You did… / You were…”. Keep warm second-person address overall, but explicitly: do not begin a page with “You” or with the baby’s name, and rotate opener techniques. Give the model the menu (see B3). The repetition is literally trained in by the example openers in the prompt. Removing them and demanding variety is the direct cause-fix.
B2★ Make cross-page variety possible. Today each page is an isolated call, so it can’t know how its neighbors begin. Two options:
• (a) pass each call the opening lines already used (“do not open like any of these”), or
• (b) recommended: generate the whole set in one batched call returning JSON [{sourceKey, body, pullQuote}], so the model varies openings across all pages at once.		 (b) is cleaner, cheaper, faster (1 call vs N), guarantees whole-book variety, and naturally carries the A2 fields. It does change the credit model (currently 1 credit/page) — call that out for the plan.
B3 Round-robin an openerStyle across pages and pass it into each prompt, e.g.: sensory image · season/age · a sound or near-quote · small action then turn to “you” · a question · direct address with a fresh verb (“Your laugh arrived today.”). Deterministic variety even if the model drifts toward its default.
B4 Vary closings too. The woven SYSTEM_PROMPT forces a forward-looking closing line on every chapter — repetitive across the book. Make it optional / rotate it. Removes a second source of sameness in the One Story path.

Layout / render-side frontend

#RecommendationWhy it helps
B5 Per-page title / date / age header (memory title + date label). Gives each page a distinct beat and a sense of progression instead of an undifferentiated stream.
B6 Rotate template / accent per consecutive page — alternate photo side, alternate a background tint from theme.palette, drop-cap some pages. Visual variety so the eye registers separate pages even when the prose is uniform.
B7 (Optional) section dividers / thematic grouping pages. Structural punctuation between groups of memories.

4 · Recommended prompt rewrites

4a · New SINGLE_ENTRY_SYSTEM_PROMPT (drop-in, per-page calls)

Implements A1 + B1 + B3. Note the rotating opener is injected per call ({openerStyle}).

You are writing a single page in a baby's keepsake memory book, capturing one moment.
Write warmly, in second person addressed to the baby, but with a natural storyteller's voice.

OPENING (important): Do NOT begin with the word "You" or with the baby's name. Open using
this technique for this page: {openerStyle}. Vary your sentence rhythm.

LENGTH: 2–3 short paragraphs, about 90–160 words — enough to fill a printed page without
feeling thin. Earn the length; do not list or repeat.

YOU MAY: add a gentle reflective beat, and lightly evoke the season or the baby's age, to
round out the page.
YOU MAY NOT: invent specific events, people, places, words spoken, or feelings that are not
in the source. When unsure who was present, write "the people who love you".

ALSO RETURN: a one-line "pullQuote" — a short, lyrical line drawn from the page (≤ 12 words).

STRICT: only reference people/relationships explicitly named; never assume parent count or
gender; heartfelt and warm, never saccharine; no title, no photo markers.

Return JSON only: { "body": "...", "pullQuote": "..." }

Opener-technique pool to round-robin into {openerStyle}:

1. a sensory image (light, sound, texture)
2. the season or the baby's age ("At four months, the world got louder.")
3. a small sound or near-word the baby made
4. a small action, then turn to address the baby
5. a gentle question
6. direct address with a fresh subject/verb ("Your laugh arrived today.")

4b · Recommended: one batched call (B2 option b)

Replace the N independent calls in generatePages() with a single call that receives all selected memories and returns an array. The model then guarantees variety across the whole set, and you get the A2 decorative fields for free.

SYSTEM: You are composing the pages of a baby's keepsake book — one page per memory,
in order. Across the whole set, every page must OPEN DIFFERENTLY: never start two pages
the same way, and never start a page with "You" or the baby's name. Rotate among:
sensory image · season/age · a sound · an action-then-address · a question · fresh
direct address. Each page: warm second person, 90–160 words, 2–3 short paragraphs.
[…carry over the STRICT no-inference rules verbatim…]

Return JSON only:
{ "pages": [ { "sourceKey": "journal:42", "body": "...", "pullQuote": "..." }, … ] }

USER:  Baby: {name}
       Memory 1 — journal:42 — Week 6: "First bath"
       {story} [Parent's memory: {note}]
       Memory 2 — first_time:9 — "First smile"
       …

Trade-off to decide in the plan: batching changes today’s “1 credit per page” billing (it’d be 1 call). Either keep per-page credit accounting in code, or revisit the credit model.

4c · Woven SYSTEM_PROMPT tweaks (One Story path)

  • Add: “Vary how each paragraph opens; do not begin consecutive paragraphs with ‘You’.”
  • Make the forced forward-looking closing (B4) optional rather than mandatory.

5 · Suggested shape of the implementation plan

This naturally becomes a small full-stack plan (next free number after the current S5.x set, e.g. s5.46-prose-variety-and-fill.md). A sensible ordering:

  1. backend Rewrite SINGLE_ENTRY_SYSTEM_PROMPT (A1 + B1) and add the round-robin openerStyle + return pullQuote (4a). Bump generateSingle max tokens (220 → ~320) to fit the longer target.
  2. backend (Optional, recommended) batched generate-pages call returning JSON (4b); decide credit handling.
  3. frontend fitText grow-to-fill + vertical centering (A4) — smallest change, biggest visible win for short pages.
  4. frontend Content-aware generated-page templates (A5) + date/age header + pull-quote block (A2, B5).
  5. frontend Per-page template/accent rotation (B6).

Steps 1 and 3 alone resolve the bulk of both complaints; the rest is polish and can be staged.
