# S5.3 — Standalone Photo Uploads

**Status: Needs Verification**
**Branch:** journal-updates
**Depends on:** S5.2 (edit mode, page reordering)

---

## Overview

Photo blocks in the layout editor can only pull from journal entries and first times (via the photo tray). Users can't add personal photos directly — e.g., a family photo, a hospital wristband shot, or anything not captured in the journal.

This session adds an **"Upload photo"** option to the photo tray. The uploaded photo is stored in Cloudinary, associated with the chapter via a new `chapter_photos` JSONB column, and available in the tray for any block in the same chapter.

---

## Storage Approach

**Option A — New `chapter_photos` JSONB column** (chosen):
- `V31__chapter_photos.sql`: `ALTER TABLE chapters ADD COLUMN chapter_photos JSONB`
- Each entry: `{ "key": "upload:uuid", "url": "https://...", "label": "My caption" }`
- PATCH endpoint already exists — just add `chapterPhotos` to `UpdateChapterRequest`

`photoOverrides` was designed to override specific journal entries, not store net-new photos — don't reuse it.

## Backend Changes

### V31__chapter_photos.sql
```sql
ALTER TABLE chapters ADD COLUMN chapter_photos JSONB;
```

### ChapterResponse.java
Add field:
```java
List<Map<String,Object>> chapterPhotos
```
Read from `chapter_photos` column (deserialize JSON array, default to empty list).

### StorybookService.java
- `getChapter()` / `getChapters()`: read `chapter_photos` from result set
- `updateChapter()`: if `chapterPhotos` in request, serialize and write to `chapter_photos`
- New method `uploadChapterPhoto(long chapterId, MultipartFile file, long userId)`:
  1. Ownership check (same pattern as existing photo upload)
  2. Upload to Cloudinary via existing `CloudinaryService` (or inline upload)
  3. Build entry: `{ "key": "upload:<uuid>", "url": "<cloudinary_url>", "label": null }`
  4. Append to `chapter_photos` array via JSONB update
  5. Return the new entry

### StorybookController.java
New endpoint:
```
POST /storybook/{id}/chapter-photos   (multipart/form-data, file field)
```
- Auth-protected (JWT)
- Calls `storybookService.uploadChapterPhoto(id, file, principalUserId)`
- Returns `{ key, url, label }` on success

## Frontend Changes

### LayoutEditor.jsx — PhotoTray

Add `chapterPhotos` prop (array of `{ sourceKey, url, label }`).

Inside `PhotoTray`, add an "Upload a photo" button at the top:
```jsx
<label className="flex items-center gap-2 px-3 py-2 rounded-lg border border-dashed border-color-highlight/40 hover:border-color-highlight/70 hover:bg-color-warm/10 cursor-pointer transition-colors text-sm text-muted-foreground">
  <Upload className="w-4 h-4 text-color-highlight/60" />
  Upload a photo
  <input type="file" accept="image/*" className="hidden" onChange={onUploadPhoto} />
</label>
```

The `onUploadPhoto` handler:
1. Reads the selected file
2. Shows an inline spinner in the tray
3. POSTs to `/storybook/{chapterId}/chapter-photos`
4. On success: calls `onChapterPhotoAdded({ sourceKey, url, label })` to add it to the tray + immediately assign it to the block that opened the tray
5. On error: shows error message

### LayoutEditor.jsx — availablePhotos

Include `chapter.chapterPhotos` in the `availablePhotos` memo (they already have `sourceKey`, `url`, `label`).

### StorybookWizard.jsx / StorybookTab.jsx

No changes needed — `chapter.chapterPhotos` flows through `onUpdate` → chapter state → LayoutEditor naturally.
