# S5.9 — Storybook PDF Export

**Status: In Progress**
**Branch:** journal-updates
**Depends on:** S5.45 (layout pages, themes, fonts)

---

## Goal

A **Download PDF** button on the Storybook tab that exports the book as a PDF matching the on-screen view 1:1 — same fonts, same block positions, same photo crops, same text sizing.

---

## Why the First Attempt Failed

The first implementation built DOM elements manually (`buildPageElement`) and set inline styles to approximate what `LayoutRenderer` renders. This failed because:

1. **Font lookup was broken** — used `theme.fontKey` (doesn't exist) instead of `theme.fontClass`, causing every page to fall back to Georgia.
2. **Cover capture picked up the live app** — `position: fixed; top: 0; left: -9999px` placed the element at y=0 in the fixed layer, so html2canvas picked up the app's UI in the background when `backgroundColor: null` was used.
3. **`useFittedFontSize` never ran** — the manual DOM element didn't go through React, so no layout effects ran, and text sizing was wrong.
4. **Drop cap required separate suppression** — the `.book-rich::first-letter` CSS rule fired on manually-classed elements.

All of these collapse into one root cause: **reimplementing the renderer produces a different result**. The fix is to use the actual renderer.

---

## Correct Approach — Render LayoutRenderer Off-Screen

### Core Idea

`ReactDOM.createRoot` → render `<LayoutRenderer>` at exactly 600px wide → `html2canvas` captures it → add to jsPDF.

At 600px container width, `LayoutRenderer`'s `scale = containerSize / CANVAS_W = 600 / 600 = 1`. The CSS `transform: scale(1)` is a no-op, so html2canvas sees the exact 600×800 virtual canvas with no distortion. It is literally capturing the same thing the user sees on screen, just unscaled.

### `captureComponent(jsx, bgColor)` utility

```
1. Create a wrapper div:
     position:absolute; top:-9999px; left:0; width:600px; height:800px; overflow:hidden
   (absolute NOT fixed — fixed overlays the viewport at y=0 which bleeds into captures)

2. Append to document.body

3. ReactDOM.createRoot(wrapper).render(jsx)

4. Wait 400ms — enough for:
   - ResizeObserver to fire and set containerSize=600 in LayoutRenderer
   - React to re-render with scale=1
   - useLayoutEffect (useFittedFontSize) to run and correctly size all text blocks

5. await document.fonts.ready

6. Wait for all <img> elements to finish loading (img.complete / img.onload)

7. Wait 100ms additional settle

8. html2canvas(wrapper, {
     useCORS: true,
     scale: 2,           ← 1200×1600px output for print quality
     width: 600,
     height: 800,
     backgroundColor: bgColor,   ← NOT null; null causes transparency bleed
     logging: false,
   })

9. root.unmount(); wrapper.remove()

10. Return canvas.toDataURL('image/jpeg', 0.92)
```

### Per-chapter, per-page capture

For **v2 layout chapters**, for each page object in `chapter.layoutData.pages`:

```jsx
<LayoutRenderer
  layout={{ version: 2, pages: [page] }}
  theme={theme}
/>
```

Single-page layout → no pagination UI renders (LayoutRenderer shows nav only when `pages.length > 1`). Every block — text, photo — renders identically to the on-screen view.

**Why this works for text sizing:** `useFittedFontSize` is a `useLayoutEffect` hook. It runs after every render, measures `scrollHeight` vs `clientHeight` in real DOM layout, and binary-searches the correct font size. Since the element is in the real DOM (just off-screen), measurements are accurate. The 400ms wait gives React time to complete this cycle before capture.

### Cover page

`BookCover` has camera upload and subtitle edit controls that would appear in the capture. Instead, the cover is a standalone read-only DOM element (no React needed — it's just a photo + text, no layout effects):

- `position:absolute; top:-9999px` (not fixed)
- Background color from `theme.bg`
- Cover photo via `<img crossOrigin="anonymous">` or placeholder div if no photo
- Baby name in the correct font family (via `FONT_CLASS_MAP[theme.fontClass]`)
- Subtitle below
- Captured with an explicit `backgroundColor` matching `theme.bg`

### Classic (non-layout) chapters

Render a plain div containing the chapter title, divider, and body text — same structure as the on-screen published view. No React hooks needed.

## Font Lookup

`LayoutRenderer` uses Tailwind classes and these apply automatically because the stylesheet is loaded. For the cover and classic chapter DOM elements only, a `FONT_CLASS_MAP` translates `theme.fontClass` to a CSS `font-family` string:

```
'font-serif'   → 'Georgia, serif'
'font-playf'   → '"Playfair Display", Georgia, serif'
'font-merri'   → '"Merriweather", Georgia, serif'
'font-sans'    → 'system-ui, sans-serif'
'font-lato'    → '"Lato", system-ui, sans-serif'
'font-nunito'  → '"Nunito", system-ui, sans-serif'
'font-display' → '"Poppins", system-ui, sans-serif'
```

## Sticker Removal (done)

Sticker blocks were removed from `buildGeneratedPageBlocks` in `StorybookWizard.jsx`. The `QUOTE_ACCENTS` constant was also removed. Quote-card (short text-only) pages now seat pull-quote and body slightly higher to fill the freed space.

Stickers are still available as a manual tool in the Layout Editor, but will not render in the PDF (html2canvas doesn't support CSS `mask-image`). An empty space will appear where a user-placed sticker was — acceptable known limitation.

## Performance

Each page = one React render + one html2canvas capture ≈ 600–900ms.
A 10-page book takes roughly 8–12 seconds. Acceptable for an export; the spinner communicates the wait.

---

## Known Limitations

- **Manually-placed sticker blocks** render as empty space in the PDF.
- **Very large books** (20+ pages) will take 20+ seconds.

## Verification

1. Generate a "One Page Per Memory" chapter with a mix of short, long, photo, no-photo memories.
2. Publish it.
3. Click **Download PDF** — spinner appears during export.
4. Open the PDF. Each page must match the on-screen layout:
   - Same font as the selected book theme
   - Text sized to fill its block (not just base size)
   - Photos in correct position and cropped correctly
   - No drop cap artifacts
   - No dark background / readability issues
5. Cover page appears first with baby name, subtitle, cover photo or placeholder.
6. Multi-page chapters: all pages appear, one per PDF page.
