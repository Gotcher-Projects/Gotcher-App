## Goal

Two things:

## Context

System prompt lives in `Backend/src/main/java/com/gotcherapp/api/storybook/ClaudeClient.java` — `SYSTEM_PROMPT` static field (~line 18).

User prompt is assembled by `StorybookService.buildWizardPrompt()` / `buildPrompt()` which pull from:
- `journal_entries` (title + story + week)
- `first_times` (label + notes)
- `milestones` (achieved milestone keys decoded to labels)
- Supplementary notes and per-entry parent notes if present

Demo user: `demo@gotcherapp.com` / `DemoPass1`, baby **Lily**, seeded by `seed-demo-user.sh` in root.

Model config: `${anthropic.model}` from `application.properties`, temperature `0.3`.

## Step 1 — Build the test script

**File:** `test-prompt.sh` (root of repo)

The script should:
1. Accept `--period START-END` (weeks, e.g. `0-12`) and optionally `--user EMAIL` (default: `demo@gotcherapp.com`)
2. Use `docker exec` to query the local Postgres container for:
   - Baby name + DOB
   - Journal entries in the week range
   - First times in the week range
   - Achieved milestones in the week range
3. Assemble the same user prompt format that `StorybookService` builds (match it exactly)
4. Print `[PROMPT SENT]` section with system prompt + user prompt
5. Call the Claude API via `curl` using `$ANTHROPIC_API_KEY` and the same model/temperature as `application.properties`
6. Print `[CLAUDE RESPONSE]` section

The script does NOT need to support wizard-mode per-entry notes or photo overrides — plain period prompt is enough for tuning.

**Match this prompt format (from `StorybookService`):**
```
Baby: Lily
Chapter: <label>
Time period: weeks <start>–<end> of life

Memories from this time:
- [Week N] <title>: <story>
- <first time label> (<notes>)

Other milestones achieved around this time:
- <label>
```

## Step 2 — Evaluate prompt options against demo data

Run the script with weeks 0–12 (and optionally 12–24) and evaluate output quality.

### Option A — Richer age anchoring
Add the baby's exact age in weeks/months at the start of each entry line, and prepend the chapter with a human-readable age span ("weeks 0–12 = newborn through 3 months").

**Why:** The model currently has no sense of developmental scale — "week 3" vs "week 11" both feel abstract. Anchoring to months may produce more naturally paced prose.

**Change:** In `buildPrompt` / `buildWizardPrompt`, convert `periodStartWeeks` / `periodEndWeeks` to "X months" and include in the chapter header line.

### Option B — Structural guidance
Add a closing instruction telling Claude how to open and close the chapter:
- Open: ground the reader in a specific moment or sensory detail from the earliest entry
- Close: a brief forward-looking line ("The months ahead would bring...")

**Why:** Without structure hints, chapters sometimes start generically ("During these early weeks...") and end abruptly.

**Change:** Add 2 sentences to the end of `SYSTEM_PROMPT`.

### Option C — Milestone framing
Currently milestones are just a bullet list. Change them to be presented as achievements with a brief developmental framing:

```
Milestones Lily reached during this time:
- Turns toward voices (a sign her hearing is developing beautifully)
- Lifts head during tummy time (building the neck strength she'll need to sit up)
```

**Why:** The model tends to ignore or flatly restate milestone bullets. Richer context may produce more meaningful prose around them.

**Change:** Expand `MILESTONE_LABELS` map to include a short "why it matters" per entry, emit them differently in `appendMilestonesContext`.

### Option D — Temperature increase
Raise temperature from `0.3` → `0.6` in `application.properties`.

**Why:** At 0.3 the output is consistent but can feel formulaic, especially for short entries. Higher temperature may produce warmer, more varied prose.

**Risk:** Too high (>0.7) and the model starts hallucinating details. Evaluate 0.5 and 0.6 via the test script before committing.

**Change:** `anthropic.temperature=0.6` in `application.properties` (or test via `--temperature` flag in the test script).

### Option E — Demo user data improvements
The demo user's journal entries may be too sparse to produce rich chapters. Evaluate by running the script and reading the output — if the chapter feels thin, update `seed-demo-user.sh` to add:
- More entries per week (2–3 instead of 1)
- Longer story text (3–4 sentences per entry, not 1)
- A mix of emotional + practical notes ("She slept for 4 hours straight and I cried with relief")
- A few first times with notes in the 0–12 week window
