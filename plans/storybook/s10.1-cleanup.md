## Goal

Finish the cut-over by removing the now-unreachable single-narrative machinery and the legacy
body-rendering paths, and deleting pre-rewrite chapters. After this session the page/`layoutData`
model is the only model end-to-end and there is no dead "classic" code.

> **Destructive.** This deletes user chapters and removes backend endpoints. Confirm before running
> the migration. Pre-launch / dev + demo only.

---

## Scope

### 1. StorybookTab — remove legacy rendering (do this first; it's the safest visible cleanup)
- `components/tabs/StorybookTab.jsx` `ChapterCard`:
  - Remove the classic inline-textarea body editing (`editing`/`editBody`/`handleSaveEdit`,
    `onUpdate(body)`), the `renderDraftBody` / `renderPublishedBody` branches, and the
    `wizardPhotoItems` / `ChapterPhoto` fallback.
  - Remove the **"Use classic style"** buttons (`clearLayoutData`) in both draft + published cards.
  - Every chapter now has `layoutData` → render only via `LayoutRenderer`; **Edit** always opens the
    builder (`onEditLayout`). Drop the `hasLayout` conditionals (always true).
  - Remove `handleGenerate` / `Regenerate` (single-body regeneration) from `ChapterCard`, and the
    now-unused `onGenerate` plumbing into the wizard.
- `components/storybook/LegacyChapterRenderer.jsx` — delete once `StorybookTab` no longer imports
  `renderPublishedBody` / `renderDraftBody` / `ChapterPhoto`. Grep first.

### 2. Backend — remove single-narrative generation
- `StorybookController.java` — remove the `POST /storybook/generate` endpoint.
- `StorybookService.java` — remove the single-narrative generate path (the non-`skipGeneration`
  wizard body generation + the `generate(id)` regeneration that writes `body`). Keep the batched
  page generation (`generate-pages`, `generatePagesBatch`).
- `ClaudeClient.java` — remove `SYSTEM_PROMPT` + `generateChapter`; keep `BATCH_PAGES_SYSTEM_PROMPT`
  + `generatePagesBatch`.
- Grep the frontend for any remaining caller of the `generate` endpoint / `onGenerate`.

### 3. DB — delete pre-rewrite chapters (no back-compat)
- New migration `Backend/db/migration/V35__drop_legacy_chapters.sql` (next free V-number) that
  deletes chapters with no v2 `layout_data` (e.g. `WHERE layout_data IS NULL OR
  layout_data->>'version' <> '2'`), plus dependent rows (chapter photos, etc.) — confirm FK/cascade.
- Update `seed-demo-user.sh` so the demo account produces builder-compatible (v2) chapters.
