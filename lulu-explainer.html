Lulu, for printing a physical storybook

What Lulu print-on-demand is, what you set up on the business side, and what the code does — for letting Plus users order a real printed book. Note up front: this feature depends on Stripe first.

Customer pays us (Stripe)→ We build a print PDF→ POST paid print job→ Lulu prints & ships

1What Lulu is

A print-on-demand company: they print and ship one book at a time, no inventory.

Lulu (lulu.com) manufactures books to order. There's no warehouse, no minimum run — when a customer wants a copy, we send Lulu a finished PDF and a shipping address, and Lulu prints that single book and drop-ships it to the customer. We never touch paper.

The piece we integrate with is the Lulu Print API (their developer product, at developers.lulu.com) — not the consumer self-publishing wizard on the main site. The API is how our server submits print jobs automatically.

The key ideaLulu is a vendor we pay, like a printing shop with an API. Our code assembles a print-ready PDF, asks Lulu what it'll cost, and — after the customer has paid us — tells Lulu to print and ship it.

2Our specific setup

From sv2-s12-print.md + lulu-print-handoff.md — and one decision that changed the whole shape of it.

The decision that matters most (resolved 2026-07-01)Lulu's Print API checkout is "External to Lulu." We are the merchant of record: the customer pays us via our own Stripe checkout, and only then do we POST a paid print job that Lulu auto-charges to a company card. So print depends on the Stripe work — see the Stripe explainer.

3Money flow

Lulu is the money-OUT side — the mirror image of Stripe.

Customer  → pays →  us, via Stripe (money IN)   •   us  → pays →  Lulu, via company card (money OUT)  →  Lulu prints & ships.

Because the customer pays us, not Lulu, Lulu needs a company card on file — not a payout bank account. (Lulu also has a separate retail/bookstore product where they sell your book and pay you royalties — we are deliberately not using that, so no bank account gets linked.) Our margin is the gap between what the customer paid us and Lulu's wholesale print + ship cost.

4Owner  What you set up

Account creation, a company card, credentials — and confirming the print spec that the code is blocked on.

The step-by-step, non-technical walkthrough is in handoffs/lulu-account-handoff.md, and the full list of spec questions is in lulu-print-handoff.md. Here's the shape of it:

  1. Create the Lulu developer account under the LLC at developers.lulu.com — the Print API product, not the consumer publishing wizard.
  2. Business + tax profile + company card — Lulu charges this card per print order. No bank account (we're not using their retail royalties product).
  3. Get credentials for BOTH sandbox and production — a client key + client secret per environment. The developer builds against sandbox first. Note both base URLs.
  4. Confirm the print spec from Lulu's product catalog — this is the part that unblocks engineering (see the callout below).
  5. Check two policy points: is white-label / unbranded shipping available (the keepsake shouldn't arrive branded "Lulu"), and does Lulu's API permit order submission from a subscription app?

5Dev  What the code does

Get a token, build two PDFs, price it, take payment via Stripe, submit a paid print job.

  1. Authenticate — exchange the client key/secret for a short-lived OAuth access token (client-credentials grant). Tokens expire in minutes; fetch a fresh one as needed.
  2. Assemble the PDFs — with OpenPDF, server-side, at 300 DPI with embedded fonts, reproducing every v2 page type. Interior and cover are typically separate PDFs. Host them at URLs Lulu can fetch.
  3. Estimate cost — call the cost-calculation endpoint before checkout so we can show the customer print + shipping + delivery time.
  4. Collect payment — via our own Stripe checkout (this is the external-checkout dependency).
  5. Submit a paid print job — POST to /print-jobs/ with the package id, PDF URLs, quantity, and shipping address. Lulu charges the company card and prints.
  6. (Optional) Order-status webhook — subscribe to Lulu's status updates to notify the user when the book ships.
The min-page gateBefore offering "Order a printed book," check the assembled page count against Lulu's confirmed minimum. Below it, either pad with blank pages or show "add a few more memories first" instead of letting the order fail at Lulu.

6Code samples

Real Lulu Print API calls. Base URL is https://api.lulu.com (prod) or https://api.sandbox.lulu.com (sandbox). Field names are from the current OpenAPI spec.

① Get an OAuth token

Client-credentials grant. The Authorization header is Basic base64(client_key:client_secret). The token comes back with an expires_in (minutes) — cache it, refresh when stale.

bash
curl -X POST https://api.lulu.com/auth/realms/glasstree/protocol/openid-connect/token \
  -H 'Content-Type: application/x-www-form-urlencoded' \
  -H 'Authorization: Basic BASE64(client_key:client_secret)' \
  -d 'grant_type=client_credentials'
# → { "access_token": "eyJ…", "expires_in": 3600, … }
JavaLuluClient.java (sketch)
private String fetchToken() throws Exception {
    String basic = Base64.getEncoder().encodeToString(
        (clientKey + ":" + clientSecret).getBytes(UTF_8));

    HttpRequest req = HttpRequest.newBuilder()
        .uri(URI.create(luluBase + "/auth/realms/glasstree/protocol/openid-connect/token"))
        .header("Authorization", "Basic " + basic)
        .header("Content-Type", "application/x-www-form-urlencoded")
        .POST(BodyPublishers.ofString("grant_type=client_credentials"))
        .build();
    // parse access_token out of the JSON response; cache until expires_in
    return parseAccessToken(http.send(req, BodyHandlers.ofString()).body());
}

7Print-spec primer

The vocabulary behind the numbers you'll confirm with Lulu.

Trim, bleed & safe area

Trim size is the finished book's dimensions after cutting (e.g. 8×10"). Bleed is the extra ~0.125" of artwork that extends past the trim line — because industrial cutters aren't pixel-perfect, any photo that should reach the edge must run into the bleed, or a sliver of white paper shows. The mirror of bleed is the safe area: keep text and faces a comfortable margin inside the trim so nothing important gets cut off.

RGB vs CMYK

Screens mix Red/Green/Blue light; presses mix Cyan/Magenta/Yellow/blacK ink. RGB can show vivid colors ink can't, so an uncontrolled RGB→CMYK conversion can dull or shift colors. If Lulu requires CMYK, we convert deliberately; if they accept RGB, we're simpler. Confirm which.

DPI / resolution

DPI (dots per inch) is print sharpness. 300 DPI is the print standard: an 8" wide page needs ~2400 px of image. Phone photos are typically 3000+ px wide — plenty — but a small image blown up across a page will look soft. The renderer targets 300 DPI at the confirmed trim size.

Cover & spine

The cover is usually one wide PDF spanning back + spine + front as a single wrap. The spine width isn't fixed — it grows with page count and paper thickness, so it's computed per book from Lulu's formula. Interior pages are their own PDF.

Anatomy of a pod_package_id

The product SKU is a 27-character code that spells out the physical spec. Confirm the exact one from Lulu's catalog — here's how to read the example above:

Segments: trim size · color · print quality · bind · paper · paper-type · PPI · finish · linen/foil. Our real trim (likely 8×10") gives a different code — that's the number to lock in §C of the handoff.

9Glossary

Print-on-demand (POD)
Printing one book at a time when it's ordered — no inventory, no minimum run.
Print API
Lulu's developer product for submitting print jobs programmatically — distinct from the consumer self-publishing wizard.
External checkout
Lulu's model where we collect the customer's payment (via Stripe) and then submit a paid job; Lulu charges our company card. It's why print depends on the Stripe work.
pod_package_id
The 27-character SKU encoding the exact physical product (trim, color, bind, paper, finish). Confirmed from Lulu's catalog.
Trim size
The finished dimensions of the book after cutting (e.g. 8×10").
Bleed
Extra artwork extending past the trim line so edge-to-edge images don't show white after the cut.
Interior vs cover PDF
Two separate files: the interior (all inside pages) and the cover (back + spine + front as one wrap).
Spine
The bound edge; its width grows with page count and paper thickness, computed per book.
Client-credentials (OAuth)
A machine-to-machine auth grant: swap a client key + secret for a short-lived access token, no user login.
Sandbox
Lulu's test environment (separate account + base URL) where we build and place fake orders before touching production.
White-label
Unbranded shipping so the package arrives as the keepsake, not marked "Lulu." A policy point to confirm.
