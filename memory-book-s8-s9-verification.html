📖 Memory Book — Scrapbook Builder S8 + S9

What changed, and exactly how to verify it · generated 2026-06-03

Overview

The Scrapbook Builder is the new full-screen editor for a memory-book chapter. It replaces the old free-form LayoutEditor with a slot-based template system. This round delivered two sessions plus a product change:

  • S8 — Place Content + Photos: drag-and-drop and tap-to-place memory text and photos into template slots, a photo tray for choosing/uploading, and debounced draft autosave.
  • S9 — Inline Editing, Backgrounds, Publish: edit & format the AI text right in its slot, set a per-page background color, and publish the chapter.
  • Stickers removed: stickers are no longer part of the memory-book system — all sticker UI, rendering, and assets were deleted.
Where to find it in the app: open a baby profile → Storybook tab → on any chapter card choose Edit layout (the builder opens full-screen). Use the demo account demo@gotcherapp.com / DemoPass1 (baby Lily, fully seeded).

How to run it locally

# From the repo root — starts Docker (Postgres), the API (3001), and the frontend (3000)
cd Backend
./start-services.sh

# Frontend only (if services are already up):
cd Frontend
npm run dev        # http://localhost:3000

Then sign in with the demo account above and go to the Storybook tab.

✅ Verify S8 — Placing content & photos

Open the builder for a chapter that already has generated content (Lily's seeded chapters do). If a page shows "No layout yet," click Choose a layout first.

  • Drag text: from the left Memories panel, drag a memory's text row onto a text slot → the slot fills with that memory's AI text (photo markers stripped).
  • Drag photo: drag a memory's photo thumbnail onto a photo slot → the photo fills it.
  • Tap-to-place (mobile/narrow): tap a memory row (it highlights) → tap a matching slot → it places. Resize the window narrow or use device emulation to confirm it works without a mouse.
  • Wrong-type is rejected: dragging text onto a photo slot (or vice-versa) does nothing.
  • Photo tray: tap an empty photo slot → the tray opens → pick an existing photo, and also try Upload a photo → the uploaded image fills the slot.
  • Re-assign a photo: on a filled photo slot, click the small camera button → tray reopens.
  • Autosave: after any change the header shows Saving… then Saved ✓.
  • Persistence: close the builder, reopen the same chapter → your arrangement is still there.

✅ Verify S9 — Editing, backgrounds, publish

  • Edit text: tap a text slot (with no memory selected) → it becomes an editor; type to change the words.
  • Formatting: with the editor open, the toolbar above the canvas toggles bold, italic, left/center/right alignment, and S/M/L size — each renders in the slot.
  • Font family: the floating font picker on the slot switches the block's font; tapping the active font again clears the override.
  • Fit: type a lot of text → it stays fit inside the fixed slot (shrinks, no overflow).
  • Click-away commits: click the page background → editing ends and the text is saved.
  • Page background: use the Page bg swatches → the canvas background changes for that page only.
  • Publish: click Publish Chapter → the builder closes and the chapter shows as published.
  • Published view matches: view the published chapter → it renders identically (same bookCanvas render model powers builder and published view).
  • Everything persists across reload (refresh the browser, reopen the chapter).

✅ Verify sticker removal

  • The builder has no "Add Sticker" control and no sticker option anywhere.
  • The legacy Layout editor toolbar (if you reach it) also no longer shows "Add Sticker."
  • Existing chapters still open and render fine (any old sticker block simply draws nothing).
  • Code check (optional): searching the frontend for sticker returns nothing in src/.

Automated tests

New unit tests cover the memory-book data logic. Run them with:

cd Frontend
npx vitest run src/test/storybookGrouping.test.js   # 18 tests
npx vitest run                                       # full suite

The new file exercises:

  • buildMemoryList — source keys, photo overrides, no-photo handling, skipping missing ids, date sorting.
  • extractPieceText — body cleanup (photo markers + blank lines), title/caption/pullQuote, missing pieces.
  • autoSuggestGroups — long entries get their own page, short runs group up to 3, runs break on a long entry.
  • buildGroupedLayoutData — v2 output, text slot fill, photo assignment, empty photo slots.
Known pre-existing failures (not from this work): the full suite reports 2 failed in api.test.js (apiUpload) and auth.test.js (validateSession). These were already failing before these changes — they're tracked as open items in the project memory (S11) and live in files this work did not touch. Everything else (109 tests) passes, and npx vite build succeeds clean.

Notes & one open decision

  • Plans updated: plans/storybook/s8-builder-placement.md and s9-builder-editing.md are marked Needs Verification; S9's sticker scope was struck out.
  • Placement on filled slots: if you have a memory selected, tapping an already-filled slot replaces its content (not only empty slots). Tapping a filled text slot with nothing selected edits it instead. Say the word if you'd prefer placement to only target empty slots.
  • S10 setup: the editor pieces were extracted into their own modules specifically so the legacy LayoutEditor.jsx can be deleted cleanly in the S10 cutover.
