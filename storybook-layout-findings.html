Storybook Layout — Findings & Improvement Options

Why "One Page Per Memory" chapters waste real estate and clip text, and how to fix it.

Generated 2026-05-29 · Branch journal-updates · Context: follows s5.44 (theme cards, 7 fonts, virtual canvas)

TL;DR. s5.44 made the editor and the published view render at the same size — but that exposed two deeper problems they share. (1) The published chapter card is full-width and painted in the book theme color, while the actual designed page is only a 500 px centered square — so most of the card is empty themed margin. (2) Long AI-generated entries overflow a hard-coded text block height and get clipped with overflow:hidden. A third, smaller bug: header text isn't theme-aware, so the title is dark-on-dark on the Midnight theme.

2. Findings (verified against source)

A. Wasted real estate Critical

  • The published ChapterCard outer element sets backgroundColor: theme.bg with no max-width, so it stretches to the full content-column width (wide on desktop).
    Frontend/src/components/tabs/StorybookTab.jsx:411
  • Header is px-8 pt-10 pb-6 with a text-2xl title and a divider carrying mb-7 — roughly 140 px of vertical themed space stacked above the page.
    StorybookTab.jsx:413–420
  • The actual page is rendered by <LayoutRenderer> below that header.
    StorybookTab.jsx:459
  • The renderer canvas is max-w-[500px] mx-auto, a fixed 1:1 square. On a ~1000–1290 px card that leaves ~250–395 px of empty themed margin on each side.
    LayoutRenderer.jsx:78 & :132
  • Nothing narrows the chapter list — StorybookTab is dropped into the full content column.
    MemoriesTab.jsx:41–69
Net effect: in the editor (mobile) the canvas fills the width and looks full; published (desktop) the same square floats in a wide themed card and looks tiny — exactly JournalCutoff2.

B. Header text not theme-aware (dark-on-dark) Medium

The header uses app-theme color tokens, not the book theme:

  • "TIME PERIOD" → text-muted-foreground StorybookTab.jsx:414
  • Title → text-foreground StorybookTab.jsx:415
  • Date → text-muted-foreground StorybookTab.jsx:462

On Midnight (theme.textColor = #e8eaf6 over #1e2040) the title is nearly invisible. The body path already wraps content in theme.textColor (:448) — the header was simply missed.

C. Text cutoff Critical

Each generated page is built with a hard-coded text-block height, regardless of how long the AI text is:

// StorybookWizard.jsx:261–289  (handleGeneratePages)
{ type: 'text',  x: 0.04, y: 0.04, width: 0.92,
  height: photoUrl ? 0.38 : 0.92, content: ... }
{ type: 'photo', x: 0.04, y: 0.46, width: 0.92, height: 0.50, ... }
  • Font size is fixed at Math.max(9, cs*0.025) = 12.5 px on the 500 px virtual canvas; the text container is overflow:hidden (applied twice).
    LayoutRenderer.jsx:7, :20, :24 — and the same in LayoutEditor.jsx TextBlock
  • The backend asks for "1–3 short paragraphs" and allows up to 400 tokens (~300 words) per page.
    ClaudeClient.java:18–27 (SINGLE_ENTRY_SYSTEM_PROMPT) · StorybookService.java:327 & :341 (generateSingle(prompt, 400))
A 3-paragraph entry cannot fit in 38% of a 500 px square at 12.5 px / 1.8 line-height, so the tail is clipped. A 2-paragraph entry fits but leaves dead space. The block never adapts to the text.

3. Improvement options

Real estate

1 Constrain the card to a book column & let the canvas fill it Low effort · High impact

Give the published ChapterCard (and the chapter list) a book width such as max-w-[560px] mx-auto, and bump LayoutRenderer from max-w-[500px] to max-w-full so the designed page fills the card edge-to-edge. No dark side margins; published now matches what you designed in the editor.

2 Trim the header for layout chapters Low effort

Reduce pt-10 pb-6 to compact padding, shrink the title, and tighten the divider's mb-7. Reclaims ~80 px of themed space above the page so the page itself is the hero.

3 Make header text theme-aware Low effort · fixes Finding B

Apply theme.textColor (falling back to the current classes for light themes) to the TIME PERIOD label, title, and date so they stay legible on Midnight and any future dark theme.

4 Reconsider the fixed 1:1 page aspect Medium effort · Optional

A real book page is portrait, not square. Switching the canvas to e.g. 3:4 uses vertical space naturally and gives long text more room. Larger change — affects editor, renderer, and existing saved layouts — so treat as a follow-up.

Text cutoff

A. Cap generated length Cheap · complements all

Tighten SINGLE_ENTRY_SYSTEM_PROMPT to ~2 short paragraphs / ~80–110 words and lower the token budget 400 → ~220. Makes generated text reliably fit the block.

B. Shrink-to-fit font (safety net) Medium effort · robust

A shared util that measures rendered text against the block height and scales the font down to a minimum, used by both LayoutRenderer and LayoutEditor's TextBlock. Guarantees nothing is ever clipped, regardless of length.

C. Auto-size the text block from text length Medium effort

In handleGeneratePages, estimate the needed height from character count and size the text block (and shrink/relocate the photo) instead of the hard-coded 0.38. Keeps a readable font while fitting the content.

D. Auto-paginate long entries Larger effort

If an entry overflows, split it into continuation text-only pages. Best long-term reading experience; most logic. Treat as a later enhancement.

Recommended combo

Real estate: options 1 + 2 + 3 — together they eliminate the wasted margins, reclaim vertical space, and fix the dark-on-dark title.

Text cutoff: option A + B — cap the generation so text fits by default, with shrink-to-fit as a guarantee. Option C as a follow-up if you want larger photos with longer text.

Each item is independently shippable, so we can land the high-impact real-estate fixes first and verify against the JournalCutoff2 scenario before touching generation.

Fonts Minor

Already 7 (Georgia, Playfair Display, Merriweather, Inter, Lato, Nunito, Poppins) after s5.44. Optional enhancements: add more families and/or group the picker by Serif / Sans / Display so the 7-button strip reads more clearly. Low priority.
