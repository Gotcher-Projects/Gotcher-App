CradleHQ · Stripe setup

Adding our products in Stripe

How to create the four things CradleHQ sells. ~30 minutes. No coding — just the Stripe dashboard.

The one idea to hold onto: Stripe needs to know what we sell before our code can charge for it. Each thing we sell is a Product (a name) with one Price (an amount). Our code never mentions dollar amounts — it only ever refers to a Price by its id (price_1abc…). Change a price in the dashboard and the code keeps working, because it reads everything it needs from the Price itself.

1Get into the right place

  1. Go to dashboard.stripe.com and log in.
  2. Confirm you are in a Sandbox (test mode), not Live. Stripe now uses an environment / Sandbox picker (it replaced the old test-mode switch). Everything you make in a sandbox is fake-money and stays there — perfect for setup. When we go live later, these four products get recreated in Live mode and get brand-new price ids. Test and Live never share ids.
  3. Open Product catalog in the left nav.

3Create one product (repeat four times)

  1. Product catalog → ＋ Add product.
  2. Enter the Name from the table.
  3. Set the amount (e.g. 5.00) and currency USD.
  4. Set billing to One-off / One time. (See the warning below — this is the #1 mistake.)
  5. Save the product.
⚠ Gotcha #1 — billing type Stripe defaults every price to “Recurring” (a subscription). We sell nothing recurring — no monthly plan anywhere. You must switch it to One-off / One time. A price left as recurring will be rejected by our code and cost an hour of confusion later.

4Add the metadata — on the Price, not the Product

After saving, open the product, click into its Price, find the Metadata section, and add two rows exactly as in the table:

  • sku → e.g. credits_50
  • credits → e.g. 50  (use 0 for “Share unlock”)

In the current dashboard you usually can’t add price metadata while first creating the product — create it, then click into the price to edit it.

⚠ Gotcha #2 — metadata belongs on the Price When someone pays, Stripe notifies our server with an event that points at the Price. Our code reads credits and sku off that Price to decide what to grant — it never looks at the Product. Metadata sitting only on the Product is invisible to us. Put it on the Price. Don’t duplicate it onto the Product too — two copies drift apart the day someone edits one and forgets the other.
Why credits: 0 instead of leaving it off the Share-unlock price? So that every price we sell carries the same two keys. That single invariant keeps the payment code simple — read credits, grant that many, no special cases. The key that makes the share unlock special is its sku (share_only), not the zero.

5Grab each Price id

On each Price you’ll see an id that starts with price_1…. Copy all four and hand them to the developer (or paste into the app’s config).

Copy the right id Copy the price_1… id — not the prod_… id. The prod_ one is the product; our code only uses price_.

✓ Done when

  • Four products exist in the sandbox.
  • Each has a one-time USD price.
  • Each Price carries sku + credits metadata.
  • You’ve captured the four price_1… ids.
Internal setup note for CradleHQ. When moving from Sandbox to Live, repeat all of this in Live mode — the Live products get their own, different price_ ids. Never paste a Secret key (sk_…) into a document, email, or screenshot.
