The CradleHQ Stack

Everything a new developer needs to understand how this baby-tracking application is built, why each piece exists, and where to find it in the code. CradleHQ is the active product (formerly "Baby Steps"), live at cradlehq.app, shipping as a web app and a native Android app from one React codebase.

Companion docs app-context.md (root) is the dense, AI-oriented version of this same material — paste it into an AI session for accurate context. plans/storybook/storybook-context.md is the deep primer for the Storybook feature (the most complex subsystem). This HTML is the human-readable handoff.

Security

Spring Security 6 stateless filter chain

What it is

The authentication/authorization layer every request passes through before reaching a controller. Configured stateless — no server-side sessions.

Why we use it

We protect every endpoint so users only see their own data. A custom JWT filter plugs into the chain to load the user from a token.

Public (permitAll) routes
/health
/auth/register · /auth/login · /auth/refresh · /auth/logout
/auth/verify-email · /auth/forgot-password · /auth/reset-password
/admin/**            // gated separately by ADMIN_SECRET
/book/public/**      // public read-only shared storybook
// everything else → authenticated()
Where in the code
config/SecurityConfig.java security/JwtAuthFilter.java security/JwtUtil.java security/AuthPrincipal.java auth/CookieUtil.java
Project-wide error gotcha An uncaught RuntimeException in a controller re-dispatches to /error unauthenticated → surfaces as 401, not 500. Always wrap external-service calls (Cloudinary, Claude) in try/catch and return a mapped ApiError.
Auth

The Dual-Mode Auth Flow cookies for web, tokens for mobile

What it is

JWT access token (15 min) + refresh token (7 days, stored in the refresh_tokens table, rotated on every refresh). Passwords hashed with BCrypt(12). The token transport differs by platform.

Web (browser)
1. Login → API sets access_token & refresh_token as httpOnly cookies (SameSite=Lax, secure in prod)
2. Frontend sends credentials: 'include' — JavaScript never sees the tokens (XSS-safe)

Native (Capacitor / Android)
1. Login → API returns tokens in the JSON body
2. Stored in localStorage (cradlehq_access_token / _refresh_token)
3. Frontend sends Authorization: Bearer <token>, credentials: 'omit'

Server resolves either — JwtAuthFilter checks the Authorization header first, then the access_token cookie.
On 401 — api.js calls POST /auth/refresh (deduplicated), retries once, then fires a session-expired event that boots the user to login.
Where in the code
auth/AuthController.java + AuthService.java auth/CookieUtil.java Frontend/src/lib/auth.js Frontend/src/lib/api.js
Database

JdbcTemplate Raw SQL layer — no ORM

What it is

A Spring utility wrapping low-level JDBC: it manages connections, prepared statements, safe parameter binding, and exception translation — so you write plain SQL.

Why we use it (instead of Hibernate/JPA)

This app began as a Node.js project with raw SQL. The philosophy carried over: write exact SQL, see exactly what runs, no ORM surprises. There is intentionally no JPA/Hibernate anywhere.

// Select a list of rows
jdbc.query("SELECT * FROM growth_records WHERE baby_profile_id = ?",
    (rs, i) -> new GrowthRecord(rs.getLong("id"), ...), profileId);

// Insert + return generated id
jdbc.queryForObject("INSERT INTO ... RETURNING id", Long.class, args...);

// Update / delete — returns rows affected
jdbc.update("DELETE FROM ... WHERE id = ? AND baby_profile_id = ?", id, profileId);
Where in the code
*/*Service.java (every feature) baby/KeyedRecordService.java (shared base) storybook/StorybookService.java
Testing gotcha JdbcTemplate.queryForList has overloads. Mocking with 5+ args can resolve to the wrong one. If you hit PotentialStubbingProblem, add @MockitoSettings(strictness = Strictness.LENIENT).
Security

JJWT 0.12.6 JWT tokens

What it is

A Java library for creating and verifying JSON Web Tokens — compact signed strings encoding user id, email, and expiry. The server verifies the signature without a DB lookup.

Why we use it

Stateless auth. Only refresh tokens hit the database; access tokens are self-contained. The refresh token carries a jti UUID claim to avoid duplicate-key crashes on concurrent refreshes.

Where in the code
security/JwtUtil.java .env → JWT_SECRET (32+ chars) application.properties → app.jwt.*
Database

Flyway Schema migrations (V1–V33)

What it is

Version control for the database schema. It tracks applied SQL scripts and runs new ones in order on startup.

Why we use it

Every environment ends up with an identical schema automatically — no manual SQL, no drift between dev and prod.

RangeWhat it creates / changes
V1–V4users · refresh_tokens · baby_profiles · milestones
V5–V8email verification tokens · journal_entries (+image); V7 placeholder
V9–V11growth_records (+imperial units)
V12–V16sleep_logs · poop_logs · vaccine_records · appointments · first_times
V17–V20baby sex · image orientation · poop→diaper rename (+category) · type nullable
V21–V22appointment time · password_reset_tokens
V23tier (free/plus/pro) + ai_credits_remaining + credits_reset_at
V24–V33Storybook — chapters, share tokens, images, wizard columns, layout_data, chapter_photos, book_theme, book_cover
Important rule Never edit an applied migration — Flyway checksums them and refuses to start if one changed. Always add a new V##__name.sql. Next migration is V34.

AI

Anthropic Claude memory-book generation

What it is

The Storybook feature uses Claude to turn a parent's journal entries into warm, narrated "memory book" pages. Called via a direct REST request — not the Anthropic SDK.

How it works

ClaudeClient.java POSTs to api.anthropic.com/v1/messages with x-api-key + anthropic-version: 2023-06-01 using Spring's RestTemplate. Model and temperature are env-configurable; never hardcode the key.

# application.properties
anthropic.api.key=${ANTHROPIC_API_KEY:}
anthropic.model=${ANTHROPIC_MODEL:claude-haiku-4-5-20251001}
anthropic.temperature=${ANTHROPIC_TEMPERATURE:0.3}
Where in the code
storybook/ClaudeClient.java storybook/StorybookService.java plans/storybook/storybook-context.md
Credits & temporary logging Generation is gated on tier != 'free' AND ai_credits_remaining > 0; a credit is decremented before the call and refunded if it throws. A temporary [CLAUDE-DEBUG] log prints full prompts + responses (personal content) — scheduled for removal in storybook session S9.

Testing

JUnit 5 + Mockito backend unit tests

What it is

JUnit 5 runs @Test methods; Mockito replaces real dependencies (the DB) with controllable mocks. Bundled via spring-boot-starter-test.

Why we use it

Tests verify one class in isolation — no DB, no server — in milliseconds. ~20 test classes cover services and controllers.

@ExtendWith(MockitoExtension.class)
class GrowthControllerTest {
    @Mock GrowthService growthService;
    @InjectMocks GrowthController controller;

    @Test void addRecord_returns201() {
        when(growthService.addRecord(eq(1L), any())).thenReturn(RECORD);
        var result = controller.addRecord(PRINCIPAL, REQUEST);
        assertEquals(HttpStatus.CREATED, result.getStatusCode());
    }
}
Where in the code
Backend/src/test/java/com/gotcherapp/api/ Reports: Backend/build/reports/tests/test/index.html

Browser API

localStorage

What it is

Persistent key-value browser storage. Survives refreshes; private to the browser.

KeyStoresWhy
gotcherapp_userThe user object (not tokens)Render the shell immediately on reload before /auth/me confirms
cradlehq_access_token / _refresh_tokenJWTs — native app onlyWeb uses httpOnly cookies instead; these are empty on web
cradlehq-themeApp UI theme idRemember base/dark across sessions
babyStepsDataCached local app dataOffline-friendly fallback; cleared on logout
Why web auth uses cookies, not localStorage localStorage is readable by any JS on the page (XSS risk). Web tokens therefore live in httpOnly cookies. The native app has no cookie jar in the WebView, so it falls back to localStorage + Bearer headers.

Production

Caddy + Prod Deploy Hetzner VPS

What it is

Production runs on a Hetzner VPS via docker-compose.prod.yml — three containers: caddy (TLS + static files + reverse proxy), api (Spring Boot), postgres.

How routing works

Caddy auto-provisions TLS for the domain, proxies /api/* → api:3001 (stripping the prefix), and serves the SPA for everything else with an index.html fallback.

# Caddyfile
{$APP_DOMAIN} {
    handle /api/* { uri strip_prefix /api; reverse_proxy api:3001 }
    handle { root * /srv; try_files {path} /index.html; file_server }
}
www.{$APP_DOMAIN} { redir https://{$APP_DOMAIN}{uri} permanent }
Deploy
# On the VPS (user: deploy, repo: ~/gotcherapp)
git pull origin main
docker compose -f docker-compose.prod.yml up -d --build
Live https://cradlehq.app. The frontend image is built with VITE_API_URL=https://${APP_DOMAIN}/api. Full runbook: deployment-guide.html (root). Demo: demo@gotcherapp.com / DemoPass1.
